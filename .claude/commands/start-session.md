# blog-web 세션 시작

이 명령이 실행된 시점부터, 이 세션은 고영준 블로그(blog-web) 작업 전용 세션이다. 아래 두 가지를 지금 순서대로 수행한다.

## 1. 로컬 개발 서버 기동 — 반드시 서브에이전트로

메인 세션(지금 이 대화)이 직접 `pnpm dev`나 다른 Bash 명령을 실행하지 않는다. Agent 툴로 서브에이전트를 하나 스폰해서 다음을 시킨다:

- `/Users/koh/Documents/june/dev_projects/june/blog-web` 에서 `pnpm dev` 로 Astro 개발 서버를 백그라운드로 기동한다.
- 서버가 정상 응답하는지(포트 확인 등) 확인하고 결과를 보고한다.
- 참고: 현재 blog-web과 같은 시스템으로 묶인 별도 앱(admin/CMS/API 등)은 없다 — blog-web은 콘텐츠를 마크다운+git으로 직접 소유하는 단일 Astro 정적 사이트이고, 편집기(TipTap WYSIWYG)도 이 레포 안의 컴포넌트일 뿐 별도 서버가 아니다. 나중에 실제로 관련 앱이 새로 생기면 이 목록을 갱신해서 함께 기동할 것.
- 이 서브에이전트는 개발 서버 기동을 확인하면 임무가 끝나는 1회성 작업이다. 개발 서버 프로세스 자체는 백그라운드로 계속 떠 있어야 한다.

## 2. 세션 운영 모드 전환 — 지금부터 세션이 끝날 때까지 유지

이제부터 메인 세션은 사용자와의 대화 창구 역할만 한다:

- 메인 세션은 blog-web 관련 실제 작업(파일 Read/Edit, Bash 실행, git 커밋/푸시 등)을 절대 직접 하지 않는다.
- 사용자가 입력하는 메시지는 요약하거나 재해석하지 않고 **그대로(verbatim)** 서브에이전트에게 전달한다. 의도를 해석하는 것은 서브에이전트의 몫이지 메인 세션의 몫이 아니다.
- 대화 작업을 처리할 서브에이전트는 **세션당 한 번만 스폰**한다. 아직 스폰하지 않았다면(즉 이 명령 실행 후 사용자의 첫 실제 요청이 들어온 시점), 그때 Agent 툴로 스폰하면서 이름/ID를 기억해 둔다. 이후 사용자의 모든 메시지는 매번 새로 Agent를 스폰하지 말고 SendMessage로 그 동일한 서브에이전트에게 이어서 보낸다 — 컨텍스트 연속성을 유지하기 위함이다.
- 이 서브에이전트가 담당하는 일: 사용자 의도 해석, 조사, 구현, git 커밋/푸시(이 레포는 PR을 쓰지 않는다 — 항상 main 브랜치에 바로 push), 그리고 다음 액션이나 결과를 메인 세션에 보고하는 것.
- 커밋 메시지는 CLAUDE.md 컨벤션을 따른다: `post:`(새 글), `edit:`(글 수정), `feat:`/`fix:`/`chore:`(사이트 기능). 성격이 다른 변경은 커밋을 분리해서 각각 커밋한다.
- 메인 세션은 서브에이전트가 돌려준 결과와 다음 액션을 사용자에게 정리해서 전달하는 릴레이 역할만 한다. 스스로 결론을 내리거나 코드를 판단하지 않는다.
